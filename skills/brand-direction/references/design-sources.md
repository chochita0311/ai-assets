# Design source library

Use this optional index to find works by the decision a person needs to make. Search for a material, reading task or relationship. If the brief is in another language, try the equivalent English terms or the credited name of the work. A gallery is useful for discovery. Following an entry to the maker makes a specific visual claim inspectable. A new brief can start with a work outside this collection. To contribute a discovery from another project or repair a source link, see [Keep useful discoveries](#keep-useful-discoveries).

## Keep useful discoveries

**In the project.** Use the study’s existing source notes. Record the maker and work, its exact URL or local source, and the page, image, frame or interaction you inspected. Describe what the source shows, which design decision it informed, where the analogy ends and what the asset rights allow. Keep original captures, the project application, decisions and ballots with the [local study](artifact-workspace.md).

**Return a reference to the library.** During a general ai-assets export, review the public design sources already inspected in the current project or session. The same request authorizes adding those that meet the criteria below. Use the source checkout resolved for the export, the one named by the user or the one identified by the project’s existing export settings. Verify that it owns the maintained skill. An installed path or the current directory alone cannot establish that. Add qualifying entries to `skills/brand-direction/references/design-sources.md` there.

Carry over the public work, exact locator, evidence type, useful observation and limit in a form that stands on its own. A public example page created by the project can qualify on the same terms as a maker’s work. A local prototype can support a generalized usage case while its files and private project details stay with the study.

Use an English lookup phrase for the design problem and name the work as credited. Match the maker, work and locator against the existing entries. An identical observation needs no edit. Merge new support at that locator, add a distinct view or lesson where it answers another question, and preserve meaningful contrary readings.

**Match the export to the request.** Honor any category or time limit. A request to review candidates ends with the list. A usage-case export goes through the existing evidence process and its catalog when available. A request for references alone updates this library with qualifying entries. With a read-only installation, make an authorized contribution in the resolved, writable source checkout. If the applicable destination is unresolved or unavailable, leave the candidate with the study. Other installed copies receive the change through an authorized install or refresh that includes the revised library.

**When a source changes.** Check the exact locator that failed. Keep a working maker page or a surviving plate active when another image disappears. A timeout, login prompt or other inconclusive result warrants an access note. When a locator is confirmed retired, strike its descriptive label and retain its former public URL as plain code. Keep the maker, work, prior observation, evidence type and limit readable. A retired plate might read ~~Foldout, plate 2~~ (unavailable) beside its former address.

Link a verified move to the same work beside the retired locator. Give a different work its own attribution. If a redesign at the same URL changes what the page shows, distinguish the historical observation from the new one.
