# Local study workspace

Use the user's chosen destination, then an established project convention, then `<target-project>/.artifacts/brand-direction/`. The target is the product being studied. A skill-maintenance session can write a consumer's pilot there when authorized. An exercise with synthetic briefs and no separate product belongs to the project commissioning the exercise. The skill's installation directory and the shell's starting directory do not determine ownership.

At the workspace root, maintain a local `index.html` that opens the current work and links retained comparisons and decisions. One study can keep its files directly beside the index. When multiple studies coexist, put each under `studies/<descriptive-name>/` with its own entry. Use another name for a materially different study and preserve a reviewed revision before replacing its evidence. Update the existing index on return. If a separate collection needs its own index, link it from the root and keep earlier reviewed URLs reachable. Use relative links for study files and assets; identify external evidence separately.

Before saving generated material inside a Git checkout, verify it will be ignored and that no destination files are already tracked. At the default local owner, a workspace `.gitignore` containing `*` keeps its own contents local. Preserve suitable existing rules. For a new owner, create the exclusion before its artifacts. Check a real output with `git check-ignore` and the destination with `git ls-files`. Treat a tracked or overlapping destination as a conflict to resolve with the existing owner. Generated studies do not imply permission to stage, commit or publish.

Keep the originals that explain a decision, the usable specimens, their required assets and notices, and scoped review notes at this owner. A reusable public work can be recorded in those notes and [contributed to the design source library](design-sources.md#keep-useful-discoveries) when shared curation is authorized. Temporary browser profiles, intermediate renders and generator scratch belong in a task-owned temporary directory. On an authorized move, verify file contents, relative links, working entry and destination Git exclusion before retiring the old copies. Leave another skill's workspace and product source with their respective owners.
