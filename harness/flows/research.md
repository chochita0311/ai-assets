# Research Flow

## Ownership And Entry

This optional flow owns the sequence and internal return points of a selected
research task. Use the [Research Runner](../operations/research-runner.md) to
start or resume it and the [Orchestrator](../roles/orchestrator.md) to control
it. [Research Governance](../policies/research-governance.md) owns its lifecycle,
state and acceptance; [Workflow Governance](../policies/workflow-governance.md)
owns shared selection, transitions, authority and resources. The
[research-sadr method](../../skills/research-sadr/SKILL.md) owns framing, inquiry,
challenge, adjudication and evidence validation.

In a consumer, load the pinned complete local method directly from
`docs/agents/methods/research-sadr/SKILL.md`; do not assume a globally installed
skill or external source checkout supplies the same revision or content.

## Sequence

1. **Resolve the task.** The primary resolves the question, decision to inform,
   constraints, acceptance, authority and one current-state owner. On resume,
   reconcile that owner's history with current inputs before choosing work.
2. **Prepare bounded work.** Load the method, verify its package identity, and
   apply shared resource governance and research capability checks before
   dispatch. Use the method to examine framing before dividing detailed investigations. Keep
   logical responsibilities separate from the actual available actors.
3. **Investigate.** Perform or delegate bounded directions under the method.
   Preserve raw access and material constraints in packets; independent
   discovery precedes sharing author conclusions. Parallelize only admitted
   work with a useful separation and capacity that covers concurrent commitments
   and closeout under actual caps and the current plan.
4. **Integrate and choose.** Preserve initial returns before informed exchange.
   Apply the method's challenge and adjudication process; integrate supported,
   refuted and unresolved claims separately from response actions. The primary
   keeps decision-relevant findings, counterevidence and inspectable locators.
5. **Return or continue.** Select the applicable junction below, update current
   scope and evidence validity, and apply the shared resource check before any
   new or continued investigation. Reassess a planning checkpoint when reached;
   do not infer whole-task sufficiency from a worker return.
6. **Wait or close.** Apply governance's actual external-condition rule for
   waiting and its closeout checks for closure. Deliver the supported answer,
   gaps, acceptance impact, stopping reason and next discriminating action.
   Keep the current-state receipt consistent with work that actually ran.

## Return Junctions

| Condition | Next owner or phase |
| --- | --- |
| New evidence changes the framing, a hypothesis is refuted, or a material objection survives | Return to the affected inquiry phase under the method; preserve prior observations and explain changed validity. |
| A check fails or its fixture, assumptions or expected result are in dispute | Return to evidence validation before treating the failure as a finding. |
| Required evidence, tool or independent capability is unavailable | Continue unrelated feasible work with explicit limits; wait only for a real external condition, otherwise close partial with the missing observation and acceptance gap. |
| A discriminating follow-up fits authorized scope and actual caps | Reassess the current plan and closeout capacity; continue the affected direction with a bounded packet and named information gain. |
| A planning checkpoint is reached | Reassess evidence, unresolved concerns and information gain; revise the plan within existing authority and actual caps when justified. |
| An actual cap leaves only reserved closeout capacity for affected work | Stop dispatch against that resource and preserve its reserve; continue unrelated feasible work, or close under governance when the cap prevents completion. Report unmet acceptance separately. |
| Scope, authority or an unresolved required durable destination prevents the next action | Return that decision to its owner; preserve usable results and resolve only the dependent work. |
| The requested judgment is supported, including a justified null finding | Close complete only after the acceptance and closeout checks pass. |

Apply [shared transition authority](../policies/workflow-governance.md#transitions-and-authority)
when the task reaches this flow's boundary. Use
[operator continuity](../policies/operator-briefing-and-review-receipts.md) for
material direction changes and handoffs without adding persistent receipts.
